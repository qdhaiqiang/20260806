07 · How it works / Gastown roles

Gastown 多 Agent：把并行开发变成可管理的生产线。

Mayor

拆任务、建立 Convoy、分派研究/实现/测试任务、汇总结果。

Polecat

在隔离 Git worktree 中完成边界清晰的工作包。

Witness / Deacon

项目级与跨项目巡检、恢复、升级，发现卡住任务。

Refinery / Crew

合并验证门禁；人类保留范围决策、审查与验收。

我司平台采用 Gastown 包装版作为协作底座，并叠加复刻规范、质量门禁、项目模板与交接标准。
不是“多开窗口”，而是任务、状态、隔离与门禁的一套机制
此页说明角色，而非把技术细节讲得过深。核心要点是 Mayor 编排、Polecat 隔离执行、Witness/Deacon 监控、Refinery 验证、Crew 决策。

WATCHDOG Witness / Deacon 持续巡检任务健康度；异常不靠人工“刷消息”发现，而进入可追踪的恢复和升级路径。
可拆分 · 可隔离 · 可回滚 · 可追溯
讲清自动化并不等于无人负责。每一步都有 owner，真正高风险的权限、数据和生产决策仍然由 Crew 人工签收。

09 · Why multi-agent saves time

节省的不是责任，而是等待、同步与返工。

单线程交付

串行等待
  • 开发者边巡检边编码，文档后补
  • 前端、数据、测试依次排队
  • 人工催问、人工合并、人工同步状态
→

Gastown 多 Agent

并行可控
  • 研究先取证，规格成为实现依据
  • 依赖明确的工作包并行推进
  • Convoy / 巡检 / 合并门禁记录状态
并行研究、实现、测试可拆分
隔离工作包在独立 worktree 执行
门禁构建、测试、审查后再合并
追溯任务状态与交付证据可复核
不承诺固定倍数；以范围、门禁和验收证据衡量价值
解释时间口径不同：自然日、有效时段和人类直接投入不能混用。重点是把人从重复劳动转移到范围、风险与验收决策。
